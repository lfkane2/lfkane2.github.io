# Lennart Kane Portfolio — Codebase Overview

Personal portfolio website for Lennart Kane, a Mechatronics Engineering student at the University of Waterloo.
---

## Tech Stack

- **Framework:** Astro v5.8.4 (static site generator)
- **Styling:** Tailwind CSS v3.4.17 with custom config
- **Integrations:** `@astrojs/tailwind`, `@astrojs/sitemap`
- **Fonts:** DM Sans (body), Instrument Serif (display/headings), JetBrains Mono (mono/tags) — loaded via Google Fonts with `display=swap`
- **No JavaScript framework** — all interactivity is vanilla JS in `<script>` tags within Astro components

## Key Design Decisions

### Design Language
- **Clean, minimal, neutral palette** — whites, grays (neutral-50 through neutral-950), almost no color except brand logos in skills
- Rounded corners (rounded-2xl on cards), subtle borders (border-neutral-100/200), soft hover shadows
- Section headings use `.section-heading` class: uppercase, tracked-out, mono font, neutral-400

### Image Handling
- All component images use Astro's `<Image>` component from `astro:assets` with `quality={85}`, responsive `widths`, and `sizes` attributes for automatic WebP generation and responsive srcset
- Source images live in `src/assets/images/` and are imported statically in components
- `ProjectLayout.astro` uses `import.meta.glob` with `{ eager: true }` for dynamic image loading based on frontmatter `heroImage` prop, with fallback to plain `<img>` tag
- Project hero images display at natural aspect ratio (no forced crop)

### Skills Ticker (Skills.astro)
- 20 skills with real brand SVG logos (Fusion 360, CATIA V5, C++, Python, ESP32, Arduino, Git, GitHub, Excel) and custom stroke icons for generic skills (MIG Welding, Machine Shop, 3D Printing, etc.)
- Each skill tile shows a color-tinted icon background using inline `style={background: ${color}12}`
- Content is duplicated (`[...skills, ...skills]`) for seamless infinite scroll illusion
- **Auto-scroll:** delta-time `requestAnimationFrame` loop at 50px/sec leftward, frame-rate independent
- **Draggable:** Pointer Events API for unified mouse+touch, exponential moving average for velocity smoothing, smooth exponential decay back to auto-scroll speed after release
- Edge fade gradients (white-to-transparent) on left and right edges

### Scroll Animations
- `.animate-on-scroll` class: elements start invisible + translated 20px down, transition to visible on `IntersectionObserver` trigger (threshold 0.1)
- Observer initialized in `Layout.astro` base script
- Staggered delays via inline `animation-delay` styles on card grids

### Meta / SEO
- OG and Twitter meta tags in `Layout.astro` with configurable title, description, ogImage props
- Canonical URL generated from `Astro.url.pathname` + `Astro.site`
- Sitemap auto-generated by `@astrojs/sitemap` at `/sitemap-index.xml`
- `robots.txt` in public/ allows all crawlers

## Component Patterns

### Reusable CSS Classes (global.css)
- `.section-heading` — section label style
- `.card` — light card with border, hover shadow
- `.card-featured` — dark (neutral-950) card for featured experience
- `.btn-primary` — dark pill button with arrow icon
- `.btn-outline` — outlined pill button

### Layout Props
- `Layout.astro`: `{ title?, description?, ogImage? }` — defaults to "Lennart Kane | Mechatronics Engineering"
- `ProjectLayout.astro`: `{ title, subtitle, date, tags[], heroImage, description?, gallery?[] }` — gallery supports images and video embeds (YouTube iframes)
- `ExperienceLayout.astro`: `{ title, company, period, location, tags[] }`

### Data
- Experience entries are defined as an array in `Experience.astro` (not content collections)
- Project entries are defined as an array in `Projects.astro` (not content collections)
- Skills are defined as an array in `Skills.astro` with `{ name, category, color, icon }` where icon is an SVG string

## Development

```bash
npm run dev      # Start dev server (images process on-the-fly, may be slow for large files)
npm run build    # Production build with optimized images
npm run preview  # Preview production build locally
```

### Notes
- Astro processes images on-the-fly in dev mode — large source images (1MB+) may take several seconds to load initially. This is normal and doesn't affect production builds.
- The `public/images/` directory contains the original unprocessed images. The `src/assets/images/` directory contains copies that Astro's `<Image>` component processes. Both exist because some pages (like the about page skiing section) still reference `/images/` paths directly.
- There is no content collection setup — all data (projects, experience, skills) is hardcoded in component frontmatter arrays. This keeps things simple but means adding a new project requires editing both the component array and creating a new page file.
